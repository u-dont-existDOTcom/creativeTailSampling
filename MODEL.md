# Relational Multiplexity — Working Structural Model

Updated: 2026-08-15
Status: conceptual model for tail sampling and later empirical testing; not a fitted quantitative theory.

## Purpose

Translate the current multiplexity findings into explicit variables and causal claims. This is meant to make future creative-tail passes sharper and to expose hidden contradictions.

## Basic objects

Let:

- `i, j` = people;
- `f` = a function/domain (childcare, practical repair, emotional support, transport, teaching, food, emergency help, work, mediation, care during illness, etc.);
- `x_ijf` = whether/how strongly person `j` actually performs function `f` for person `i`;
- `c_ijf` = the relationship's current capability to perform that function, including competence, permission, trust, routines, contextual knowledge, and reciprocal expectations.

A relationship is **multiplex** when the same `i-j` tie has substantial `x_ijf` across several distinct functions.

## Core variables

### M — tie multiplexity

For a tie `i-j`, the number or weighted diversity of functions that the relationship actually carries.

Important: affection and contact frequency do not substitute for M.

### C — relational capability

The latent ability of a tie to carry a function safely/usefully when needed.

Working dynamic:

> use of a function tends to increase C for that function; prolonged non-use can prevent or erode capability.

This is F005.

### R — redundant multiplexity

The extent to which important functions are available through **several** capable multiplex ties rather than one all-purpose relationship.

High M with low R can create entrapment/common-person failure. The design target is not maximum M; it is sufficient M with healthy R.

### A — common access coupling

The degree to which nominally separate specialist functions depend on the same underlying access variable: money, credentials, transport, platform/phone access, eligibility, institutional permission, etc.

High A creates the F004 common-mode failure risk.

### D — decomposability of replacement

How independently the functions carried by a relationship can be replaced.

High D means each function can be substituted separately. Low D means replacement requires finding a new joint bundle or rebuilding substantial shared context.

F007 predicts that increasing D lowers combinatorial uniqueness even when the person's traits do not change.

### O — relational option value

Expected future useful functions a relationship could learn to carry because trust/context/reciprocity already exist.

O is not the same as present service output. A locally inefficient relational transaction can increase O by training the tie.

This is the key object in F010.

### N — anti-multiplexity norm pressure

The degree to which asking, offering, intervening, mixing roles, or relying on nonprofessionals is treated as inappropriate, burdensome, unsafe, intrusive, or illegitimate.

N can be healthy in some domains. The hypothesis is that high generalized N suppresses role accretion even where cross-domain help would be safe and consensual.

## Main feedback loops

### Loop L1 — capability atrophy

> outsource f -> no relational use of f -> C_ijf fails to grow -> relational provision is less attractive next time -> outsource f

### Loop L2 — replacement feedback

> unbundle functions -> D rises -> person easier to replace component-wise -> less relationship-specific investment/tolerance -> M falls -> D rises further

### Loop L3 — access coupling

> more specialist routing -> more functions depend on shared access layer -> A rises -> common access shock causes multi-domain failure -> failures routed to more specialist systems -> A can rise further

### Loop L4 — transaction optimization

> specialist performs f better now -> specialist gets task -> relationship loses learning opportunity -> specialist advantage over relationship increases -> specialist chosen again

This is the mechanism behind F010.

### Possible Loop L5 — norm adaptation

> outsource f -> ordinary ties stop carrying f -> expectation of relational help feels less realistic/legitimate -> N rises -> relational use falls -> outsource f

This remains provisional.

## Bistability hypothesis

If C and M lower the cost of adding further functions, while low C/M make relational use risky or inconvenient, the system may have at least two attractors:

### High-multiplexity attractor

- useful role exchange is normal;
- C remains high through use;
- adding adjacent functions is relatively cheap;
- O is visible enough to justify some short-run inefficiency;
- specialist services remain available where their expertise dominates.

### Low-multiplexity attractor

- most useful functions are routed away from ordinary ties;
- C remains low because ties do not practice;
- asking/allowing role overlap feels risky or inappropriate;
- specialist advantage becomes self-confirming;
- many functions depend on common system-access layers;
- people can have substantial sociability without functional community.

This is F008/F009.

## Discriminating predictions

### P1 — role exchange should beat contact-only community building

Holding social contact roughly constant, groups that repeatedly exchange real useful low-stakes functions should develop greater later crisis-support capacity than groups centered on conversation/social events alone.

### P2 — early inefficiency can predict later resilience

A group permitted to perform some tasks internally despite initially lower efficiency should improve its internal functional capacity faster than a comparable group that always purchases the best specialist option.

### P3 — income/access shocks should reveal hidden common-mode coupling

Where A is high, a shock to a common access variable should cause simultaneous loss across several nominally independent functions. High redundant multiplexity R should buffer this covariance.

### P4 — interpersonal rupture distinguishes bad multiplex concentration from healthy redundant multiplexity

High M concentrated in one relationship should make rupture unusually destructive. High M distributed across several ties should reduce this effect.

### P5 — role overlap should predict support better than friend count

After controlling for tie strength/contact frequency, actual function overlap and coverage redundancy should better predict practical support under disruption.

### P6 — component-wise substitutability should predict lower investment

Where roles can be independently replaced with low switching cost, relationship-specific investment should be lower than in otherwise similar ties where value depends on a joint bundle.

### P7 — marginal sociability interventions may show threshold failure

In a low-M/low-C state, small increases in contact may do almost nothing. Coordinated role-sharing may produce nonlinear gains if it crosses a capability threshold.

## Falsifiers / danger signs

The current model weakens substantially if evidence shows any of the following:

- role overlap adds little predictive power beyond affection/contact/tie strength;
- real function-sharing does not increase later relational capability;
- high specialist use does not reduce later informal role capacity;
- common access shocks are not buffered by multiplex networks after controlling for material resources;
- relational investment is unrelated to joint-bundle replacement difficulty;
- community recovery is approximately linear in social contact with no meaningful role-sharing threshold.

## Design constraint

Do **not** infer "replace professionals with friends." High-stakes expertise, privacy, consent, clean exit, and specialized competence remain valuable. The hypothesis is narrower: routing *every* useful function through specialists may eliminate the practice processes required for ordinary relationships to become capable, leaving a system with high specialist competence but low relational option value.
